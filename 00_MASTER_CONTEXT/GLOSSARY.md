# Glosario de ALBRA

- Estado: PROPOSED
- Versión: 0.1.0

| Término | Definición de trabajo |
|---|---|
| ADN | Identidad, principios, invariantes, límites, contratos fundamentales y gobernanza que deben mantenerse coherentes al cambiar capacidades. |
| ALBRA-CONTEXT | Repositorio público de memoria externa versionada, decisiones, estado y referencias de ALBRA. |
| Agente General | Organismo base universal que aporta estructura común; no se define principalmente como coordinador de otros agentes. |
| Agente especializado | Agente que conserva el ADN común y añade misión, contratos y capacidades particulares. |
| Bootstrap | Documento de entrada que indica cómo orientarse, qué leer y cómo trabajar con el contexto. |
| Capacidad | Función o recurso incorporable o sustituible, como una herramienta, API, conector, MCP, software o servicio externo. |
| Capability Contract | Contrato que describe la interfaz, límites, requisitos y comportamiento esperado de una capacidad. |
| Capability Registry | Registro de capacidades disponibles, su estado y sus metadatos pertinentes. |
| Adapter / Connector | Componente de integración entre ALBRA y una capacidad externa. |
| Seed congelado | Versión identificada y protegida de un artefacto base que no debe cambiarse sin autorización y decisión explícitas. |
| Fuente canónica | Documento designado como referencia principal para un concepto o una regla. |
| Evidencia | Material verificable, como un commit, código, resultado de prueba o registro de ejecución, que respalda una afirmación factual. |
| Aprobación | Decisión normativa explícita de una persona o proceso autorizado. No equivale a verificación técnica. |
| Verificación | Comprobación mediante evidencia de que una afirmación o resultado se sostiene dentro de un alcance definido. |
| Portabilidad | Capacidad de trasladar contexto y procedimientos entre cuentas, modelos, conversaciones y plataformas mediante documentos y referencias explícitas. |

## Notas

- Las definiciones son iniciales y deben alinearse con contratos y decisiones canónicas cuando existan.
- Los términos técnicos en inglés se conservan cuando son nombres de componentes o conceptos de arquitectura.
- Una palabra en el glosario no constituye por sí sola un contrato implementado.
